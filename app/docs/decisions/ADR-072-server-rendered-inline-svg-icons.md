# ADR-072: Server-Rendered Inline-SVG Icons

**Status:** Implemented (#452 2026-06-30; validation hardened #453/#454 + this change)

**Date:** 2026-06-30

**Decision Type:** ✅ Pattern/Practice  ⬜ Infrastructure  ⬜ Architecture

**Related ADRs:**
- Supersedes: **ADR-071 Decision 3 ("Lucide JS as the icon strategy")** — the client-side
  `lucide.createIcons()` / `data-lucide` runtime is removed. ADR-071 otherwise stands
  (Tailwind component layer, CSS ownership, Tailwind CLI compilation).
- Depends on: ADR-050 (PWA / static serving)

---

## Context

ADR-071 replaced MonsterUI's `UkIcon` with a vendored Lucide JS runtime: icons were authored
as `<i data-lucide="check">` placeholders, and `lucide.createIcons()` scanned the DOM to swap
each placeholder for an `<svg>` — once after Alpine init and again on every HTMX swap. A
`MutationObserver` re-ran the scan when reactive (`x-for`/`x-if`) DOM appeared.

That model caused two browser-freezing incidents:

1. **The MutationObserver infinite loop (#450).** `createIcons()` *mutates* the DOM, which
   re-fired the observer, which re-ran `createIcons()` → unbounded loop pegging a CPU core on
   **every** page (login included) → spinner-forever, swap-thrash freeze on a busy machine.
   The vendored Lucide build also *retains* `data-lucide` on the generated `<svg>`, so
   `createIcons()` is **non-idempotent** — re-scans re-process the same icons. This is in the
   minified UMD bundle (`replaceElement` hardcodes `"data-lucide"` on output), not a
   configurable build flag. #450 only *guarded* the loop (disconnect/reconnect + rAF coalesce).

2. **Masking effects** made it hard to diagnose: `skuel.js` is loaded render-blocking, and
   static files carried no `Cache-Control`, so browsers served the stale looping script
   without revalidating.

The root problem was architectural, not a bug to patch: **client-side icon rendering can loop,
costs a 410 KB JS download, blocks first paint behind a DOM scan, and ties icon correctness to
runtime JS execution.** A guard around a loop does not remove the class of failure.

---

## Decision

**Render icons server-side as inline `<svg>`. Ship zero client-side icon JS.**

```
Appearance:     Tailwind CSS (CLI-compiled output.css)          — unchanged (ADR-071)
Icons:          server-rendered inline <svg> from a generated registry   — THIS ADR
Interactivity:  Alpine.js                                       — unchanged
Server comms:   HTMX                                            — unchanged
Components:     ui/components/ — Python FT functions             — unchanged (ADR-071)
```

### Decision 1 — `Icon()` emits inline SVG, not a placeholder

`ui/components/icon.py::Icon(name, cls="", size=16, **kwargs)` returns a `NotStr` carrying a
complete inline `<svg>` whose inner geometry (`<path>`/`<circle>`/…) is looked up from a
generated registry. No `data-lucide` placeholder, no `createIcons()`, no MutationObserver. An
HTMX swap that returns markup containing `Icon()` output is already final SVG — nothing to
upgrade. Unknown names fall back to a **visible** `help-circle`, never a blank.

### Decision 2 — `ICON_PATHS` is a committed, generated registry

`ui/components/_icon_data.py` (`ICON_PATHS: dict[str, str]`) is generated by
`scripts/gen_icons.py` and committed. The generator harvests icon geometry from the **vendored
Lucide UMD bundle** (`static/vendor/lucide/lucide.<ver>.min.js`) via `node` — no network, no
new dependency. The bundle is retained **only as an offline harvest source**; it is **never
shipped to the client**. Regenerate with `uv run python scripts/gen_icons.py` after adding or
removing icons.

### Decision 3 — Harvest-by-validity, not call-shape enumeration

With the runtime gone, **any** name reaching `Icon()` must exist in the registry — whether
passed directly (`Icon("check")`), via a config field (`icon="sun"`), or through a wrapper
helper (`_icon_ghost_btn("thumbs-up")`). Rather than enumerate every call shape (whack-a-mole),
the generator includes every quoted string literal in our own source (`ui/`, `adapters/`,
`static/js/` — never `static/vendor/`) that is a real Lucide name. Cost: a few words that
happen to be icon names get included unused — harmless in a generated file.

### Decision 4 — Default size via SVG attributes, not a width class

`Icon()` applies its default `size` to the SVG `width`/`height` **attributes**, not a
`w-[Npx]` class. A width/height utility in `cls` (`w-6 h-6`, `size-5`) therefore always wins
(a CSS class overrides a presentational attribute) with no Tailwind class-order fight. This
fixed icons that silently clamped to 16px (#453).

### Decision 5 — Icon-intent literals are build-validated

Because an unknown name now fails *nowhere* at runtime (it silently renders `help-circle`),
`gen_icons.py` fails the build, and `tests/unit/scripts/test_gen_icons.py` fails CI, when an
**icon-intent literal** names a non-existent Lucide icon. Icon-intent positions are those where
a string literal can only be meant as an icon name:

- `Icon("name")` — the renderer chokepoint
- `icon="name"` — config field / keyword argument (DomainConfig, card specs, nav config, …)
- `"icon": "name"` — dict-entry config (section/template specs that flow through
  `form_generator` into `Icon(icon_name)`; the most common config shape)
- `_icon_*("name")` — underscore-prefixed wrapper helpers that forward to `Icon()`

Dynamic forms (`Icon(name)`, `icon=variable`) cannot be validated statically and are skipped.
This catches both failure modes: a typo'd name, and a real name added in code without
regenerating the registry. (CI runs `tests/unit/`, so the test gate is automatic.)

## Alternatives Considered

### Alternative A — Keep the runtime, guard the loop harder (the #450 fix)
Disconnect/reconnect the observer and coalesce with `requestAnimationFrame`. **Rejected** as
the standing model: it masks a structural failure (per SKUEL "fix the problem, don't mask it"),
keeps the 410 KB download and the first-paint DOM scan, and leaves icon correctness dependent
on runtime JS. #450 shipped it only as a stopgap; #452 removed the cause.

### Alternative B — `defer` the render-blocking `skuel.js`
**Rejected** by Mike: render-blocking `skuel.js` makes a broken script visibly stop the page
rather than silently render a half-working UI. (It would also need reordering before Alpine,
since `skuel.js` registers `Alpine.data()` in an `alpine:init` listener.)

### Alternative C — Switch the generator to `lucide-static` (`icons/*.svg`)
Reasonable and would drop the `node` dependency at generation time. **Deferred:** the vendored
UMD bundle is already pinned in-repo and `load_icon_nodes()` is a one-function swap when wanted.

### Alternative D — A semantic `IconName` port + provider-swap (Lucide ↔ HeroIcons)
Make icons fully hexagonal: a semantic `IconName` enum the app depends on, per-provider adapter
registries, and an `ICON_PROVIDER` env toggle. **Out of scope here** — a deliberate feature
decision per One Path Forward, unscheduled until a second provider is actually wanted. The
`Icon()` chokepoint is the seam it would build on; today the port still leaks Lucide's
vocabulary to call sites. Do **not** bolt a second name vocabulary onto `ICON_PATHS`.

## Consequences

### Positive
- **The freeze class of bug is structurally gone** — no client-side icon rendering exists to
  loop. No MutationObserver, no `createIcons()`.
- **410 KB removed** from every page; no first-paint DOM scan; icons present in initial HTML.
- **Icon correctness is build-time, not runtime** — typo'd icon-intent literals fail CI.
- **HTMX-swapped fragments need no re-scan** — returned markup is already final SVG.

### Negative
- Adding a *new* icon requires running `gen_icons.py` (the build/test catches a missed run).
- The vendored bundle stays in-repo as a harvest source (offline, not shipped).
- The validation covers icon-*intent* literals only; a dynamic name (`Icon(some_var)`) is still
  unvalidated by construction.

### Risks
| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| New icon used but registry not regenerated | Medium | Low | Build check + `test_gen_icons.py` fail; visible `help-circle` if it ever slips |
| Typo in an icon-intent literal | Medium | Low | Build check + CI test fail on the exact name |
| Bundle version drift vs. generated registry | Low | Low | Registry header records the source bundle filename; regenerate to resync |

## Implementation Notes

- **Renderer:** `ui/components/icon.py`
- **Registry (generated, committed):** `ui/components/_icon_data.py`
- **Generator:** `scripts/gen_icons.py` (`icon_name_literals()` is the validated-shape scanner;
  `scan_used_names()` is the permissive harvest)
- **CI gate:** `tests/unit/scripts/test_gen_icons.py`; render smoke test (`./dev smoke`, #451)
  catches client-side render hangs more broadly
- **Removed:** the Lucide `<script>`, `LUCIDE_VERSION`, every `createIcons()` caller, and the
  MutationObserver in `static/js/skuel.js`; `today.js` `x-html` icon helpers now pre-render SVG
  into the seed
