# SKUEL secret-scan — ASSIGNMENT-shape catalog.
#
# One credential name per line; `#` comments and blank lines are ignored.
# Read by scripts/git-hooks/secret-scan.sh: a staged line that assigns any name
# below a non-placeholder value is a leak, whatever the value looks like. This
# is how the prefix-free credentials get caught — Deepgram's 40 hex chars, an
# AuraDB password, SESSION_SECRET_KEY.
#
# The file has two parts, and the drift test in
# tests/unit/scripts/test_secret_scan.py pins both.
#
# 1. A MIRROR of CredentialSetup.CREDENTIALS.keys(), which it must equal exactly.
#    Bash cannot import Python, so the names are duplicated here — the same
#    arrangement scripts/lint_skuel.py::SkuelLinter.CREDENTIAL_CATALOG uses.
# 2. Credential-bearing names that are NOT funnel credentials. What makes a name
#    belong in this file is that assigning it a literal is a leak, which is a
#    wider question than whether get_credential() manages it.
#
NEO4J_PASSWORD

# --- not funnel credentials (part 2) -------------------------------------
# Docker Compose reads NEO4J_AUTH directly for ${VAR} interpolation
# (infrastructure/docker-compose.yml). It carries a real password in its
# `user/password` value, and migrate_secrets_to_homedir.py treats it as a
# secret — but it is not in CredentialSetup.CREDENTIALS and is never read
# through get_credential(), so it lives here rather than in the mirror.
NEO4J_AUTH

# The master key for the Fernet-encrypted credential store
# (core/config/credential_store.py). It is not a stored credential — it is what
# decrypts all of them, so leaking it exposes every key in the store.
# migrate_secrets_to_homedir.py already classifies it as a secret.
SKUEL_MASTER_KEY

# The signup gate. Read through get_credential() (adapters/inbound/auth_ui.py)
